## 소견

[MEDIUM] README.md:78 — "15s 내" 는 폰이 LAN 에 들어오는 시나리오에서 사실이 아니다.
  근거: 루프는 매 틱 `sleep 15` 후 접속 시도, 실패하면 `STATE=away; sleep "$AWAY_BACKOFF"`(60s) 후 `continue` -> 다시 15s. 폰 도착 후 최대 약 75s. FAILS>=5 면 틱 60s, >=20 이면 300s. 복구 분기는 추가로 `CONFIRM_WAIT=15` + 복구 확인 루프 최대 60s.
  증거(자기 로그): daemon-health.log `21:35:28 폰 접속 불가 ...` -> `21:36:43 정상` = 75s. 15s 는 이미 붙어 있다가 `adb disconnect` 한 장애주입(manifest 21:37:00->21:37:15)에만 해당.
  수정: "약 1분 내(연속 실패 누적 시 최대 5분)" 로 고치거나 "감시 주기 15s" 로 표기. 단정 숫자는 운영자가 폰 위젯 탭을 미루게 만든다.

[LOW] manifest.md installer-live — PASS 판정이 증거와 어긋난다.
  근거: installer-live.log 는 12회 모두 `dev=` 빈값(60s), installer 자신의 성공 조건(`[ -n "$DEV" ]`)이 실패한 경로. `installer-live.exit`=0 은 스크립트가 경고 경로에서도 exit 0 이라 무의미한 값이다. manifest 본문이 "폰 연결 판정은 ⚠️"라고 자인하므로 은폐는 아니나, 표 판정은 "PASS(설치) / 연결 판정 경고 -> 수동 connect 후 daemon-health 로 대체 검증" 이 정직하다. fd 3 의 판정 1줄도 로그에 안 남는다.
